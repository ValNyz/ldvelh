## Running the suite

CI sets `REQUIRE_TEST_DB=1`: a missing or unmigrated test database (or a failing `dbmate up`) FAILS the run instead of skipping tests. Locally the variable is unset and DB tests skip when no DB is reachable. `scripts/test-backend.sh` and CI generate a random `JWT_SECRET` and `ENCRYPTION_KEY` per run, and `tests/conftest.py` does the same when they are unset; never reuse a secret written in the repo (the former CI values are rejected by `startup_checks.py`).

The chat fixtures (`harness`, `scripted_llm`, `llm_mode`, `world_game`, `fate_game`, `no_api_key`, `seeded_random`) live in `tests/plugins/chat.py` and the catalog fixture `llm_table` in `tests/plugins/catalog.py`, both registered by `tests/conftest.py`, so every test package uses them without importing them; characterization tests get `seeded_random` automatically, other tests opt in with `pytestmark = pytest.mark.usefixtures("seeded_random")`. Pure helpers (`engine_state`, `stress_on_every_roll`, `insert_llm_model`) are in `tests/helpers.py`.

The world and narration payloads served by the scripted LLM are frozen under `tests/characterization/fixtures/` (`world_gen.json`, `narration.json`), so reworking `tests/prompt_examples.py` does not churn snapshots; `test_harness_smoke.py` validates them against the current schemas.

## Comment mettre à jour un snapshot

A behavior change is allowed only when it fixes an issue listed in the phase. Then:

1. Run the affected test(s) with `UPDATE_SNAPSHOTS=1` to rewrite the JSON, for example
   `UPDATE_SNAPSHOTS=1 python -m pytest tests/characterization/test_c01_c03_core_flow.py -q`.
2. Review the `git diff` of `tests/characterization/snapshots/*.json` line by line: every
   changed line must be explained by the fixed issue. An unexplained diff is a regression.
3. Cite the fixed issue in the commit message (for example `Fix director running every turn (#9)`).
4. Update the "Known bugs visible in snapshots" column of this file in the same commit
   (remove the issue that is now fixed, or add the new observation).
5. If an xfail(strict) test (C-17) starts passing, remove its xfail marker in the same commit.
